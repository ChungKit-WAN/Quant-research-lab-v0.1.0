# 量化研究框架版本路线

项目将行业 ETF 风险配置与个股因子选股统一在一个框架中，用数据与策略适配器扩展能力，共用调度、组合记账、风险约束、报告和追踪信息。版本号表示工程范围，频率提高不等于收益提高。

**当前本地版本为 v0.11（0.11.0），本次升级尚未推送 GitHub。** v0.1 的既有发布与本地旧研究报告保留。v1.0、v2.0、v3.0 是计划，不能写成已完成能力或既有实验结果。

| 版本 | 决策频率 | 主要交付 | 状态 |
| --- | --- | --- | --- |
| v0.1 | 每月 | ETF 风险配置与个股因子选股，次交易日执行、日度记账 | 既有版本 |
| v0.11 | 每月 | 研究验证、11 行业页面、全部指标排序、便携一键更新 | 本地实现 |
| v1.0 | 每日 | 同一核心支持日度信号与时间分离验证 | 规划 |
| v2.0 | 每小时 | 盘中数据、事件回放、细化交易成本与延迟 | 规划 |
| v3.0 | 分钟／秒 | AI 处理新闻论坛事件，受约束地调整策略与仓位 | 规划 |

## v0.1：月度决策，日度记账

ETF 策略包含等权、样本协方差最小方差与常相关收缩最小方差。个股策略复用既有价格／成交量因子，形成排名与选股目标，再进入共同账本。100 个候选指标中 65 个已实现；35 个价值、质量、成长指标等待具有历史可用时间的财务数据。财务指标空缺与预热不足均不应填成零分。

月末收盘后生成信号，下一交易日收盘执行，新持仓随后才开始获得收益。日度记录持仓、现金、费用、净值和回撤。“月计算”限制的是决策频率，不是只用月末价格评估风险。复权价格对应合成份额，不重复计算分红与拆股。

发布验收：

- 在独立环境安装项目并跑通 ETF、个股演示与自动化测试；合成行情明确标注为工程演示。
- 以手算用例检查信号、成交、首次建仓费用、自融资交易和净值连续性；验证输入缺口与样本末尾信号。
- 对自有或有权使用的真实数据固定批次、参数、依赖和代码版本；分别记录“复现成功”“数据独立核验”“统计推断”的状态。
- 确认仓库名称与公开范围，选择项目整体许可，检查数据与第三方源码的分发条件；再建立版本 tag 和发布说明。

历史来源见[核心迁移记录](CORE_PROVENANCE.md)。此前桌面 ETF 工程的固定报告、数据验证与敏感性结果属于原工程证据；新包的导入方式改变了源码指纹，不能用修改旧预期 SHA 的方式宣称已重放旧报告。原个股流水线说明见[存档](LEGACY_PIPELINE.md)。

## v0.11：研究验证与便携更新

包含先前讨论的 v0.1.1 小版本目标，并按本次要求命名为 v0.11。Windows 双击 `START_V011.cmd` 自动配置环境，按当前时间下载 55 只样本股与 11 行业 ETF，保存行情快照及计算数据库，再生成总览、11 行业个股排名页、ETF／个股回测和验证报告。中文英文各自成页。全部 100 项指标可查看，65 项量价指标计算值，35 项财务指标显示待数据；升降序仅影响报告查看。

默认日期随时钟滚动：最近 5 年研究、之前 3 年预热、最后 24 个月按时间划分为验证区间。行情截止到已结束且经过两小时缓冲的交易日；完整月判断依据交易所日历，上海已跨月不代表纽约月末已结束。

验证流程在运行前写出固定计划，比较 5／10／20 bp 成本、持股数量、排名平滑窗口及逐组移除评分贡献，全部结果与失败均留存。实验使用相同股票池、连续账本和对应成本的等权基准。财务数据缺失、固定样本偏差、复权数据可能修订，以及“日期留出不证明从未看过”均保留。行情样本与交易日核验属于内部一致性检查，不等于独立供应商核验。

## v1.0：每日信号，次日执行

复用同一账本和策略接口，将调度扩展到每个有效交易日收盘后，初始执行口径仍设为下一交易日收盘。若另加开盘执行，应独立验证价格、公司行动与成交假设。估计窗口与调仓频率分别配置；切换频率不能悄悄改变风险模型。

验收：交易日、缺失行情、停牌、重复数据和样本末尾信号处理有明确规则；相同数据与配置的输出可复现。月度与日度策略在同一区间比较净收益、风险、换手和费用。开发、验证、最终测试按时间分离；滚动前推验证中，训练、参数选择及特征变换只能访问当时已知数据。已被用于选参数的留出集不再属于未见测试集。

## v2.0：小时级决策

接入有明确许可、历史深度与覆盖范围的盘中行情。仅使用已结束且已接收的小时 bar；信号产生后才能执行。明确交易所时区、夏令时、常规／延长时段、半日市及尾部不足一小时区间的处理规则。

验收：事件能够回放，乱序、重复、迟到和修订数据有测试；记录事件时间、首次接收时间和可用时间。成本模型逐步增加买卖价差、滑点、流动性与成交量约束；仅凭 OHLC 不能恢复真实成交路径。历史最终修订值不能直接作为原决策时点已知值。数据商与具体接口尚未选择。

## v3.0：AI、新闻论坛与分钟／秒级事件驱动

先实现分钟级事件回放与模拟交易，再根据数据质量和实测延迟推进秒级。秒级调度不要求每秒调用大模型，也不证明订单能在秒内可靠成交。

建议处理流程：来源采集 → 原始事件留存 → 去重与修订关联 → AI 异步提取结构化特征 → 从已验证的策略集合选择并计算仓位 → 独立风险检查 → 模拟执行。AI 可提取事件类型、相关标的、情绪和置信度；策略调整受预设规则约束，不让模型临时编写并执行交易代码。

每条新闻或帖子记录来源链接、内容哈希、发布时间、首次接收时间、修订版本和提取完成时间。特征的 `available_at` 不早于输入收到和计算完成的时点；决策只能使用 `available_at <= decision_at` 的版本。后续编辑不能覆盖旧决策所见内容，转载去重，历史发布时间不能证明系统当时取得过内容。

冻结模型、提示词、特征 schema 与参数版本，保留响应及失败、延迟记录；超时、过期信息和低置信度按预设规则降级。即使输入时间正确，模型训练语料仍可能包含回测区间之后的信息；需要披露训练泄漏限制，并用冻结版本后的前瞻模拟记录验证。

验收：故障测试覆盖断网、AI 超时、重复订单、来源冲突和修订；分别测量采集、推理、排队、执行与尾部延迟。模拟交易账本完成对账，风险层限制仓位、杠杆与交易量，并具备损失阈值和停止开关。真实资金接口是独立后续范围，不由版本号自动授权。

## GitHub 与简历证据

每版保留变更记录、固定配置、可复现命令和验收结果；发布时建立对应 Git tag。仓库不包含密钥、个人运行路径、无权分发的行情或新闻正文。公开仓库便于展示，但公开可见不自动授予他人开源使用权限，许可证需单独确定。

简历描述实际完成的模块、验证方法及可检查的成果链接。收益数字必须关联数据来源、样本区间、费用、偏差限制和实验版本。合成演示证明可运行性；规划中的日度、小时、AI 功能仅列为后续工作。
